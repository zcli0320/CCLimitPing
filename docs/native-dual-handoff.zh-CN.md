# 0.3.9 单工作端、双端不同账号

2026-10-28，Asia/Singapore。首版实现已接入；完整真实Desktop冷启动交接验收尚未通过，当前自动切号保持关闭。

## 使用方式

Desktop固定使用`~/.codex`，CLI固定使用`~/.codex-cli`，历史、模型、权限、工具配置分别保留。CC Switch账号库继续作为账号来源，原生分配成功后CC Switch固定管理CLI目录。窗口同时显示两端的磁盘账号，明确不把磁盘身份当作运行实例身份。

在Desktop或CLI页签选定准确会话并开启切号，该端就是唯一工作端；CLI须从小助手托管入口启动。另一端须空闲且能确认停止。两端账号相同时优先修复待用端，工作端登录与任务不动；该修复不等待账号额度满足条件。

工作端额度低于阈值、候选账号额度可用后：准备候选账号 → 暂停准确轮次 → 确认工作端退出 → 交换两端完整登录 → 核对账号不同及CLI供应商指针 → 仅启动并继续工作端。待用端保留原工作端账号并保持停止，不因低额度再反向切号。两账号都不满足额度时等待恢复。默认阈值10%，本机最新授权为10%；阈值保存在小助手界面状态中。

CC Switch在准备期间正常退出，成功或确认尚未发布的退出超时后恢复原运行状态。原生后端不点击供应商卡片，因此切号不依赖CC Switch按钮的辅助功能授权。正常退出应用仍必须成功，不能用窗口隐藏或收到退出请求当作实际退出。

首版限制：CC Switch 4.0.21、账号库v2、两个唯一绑定的OAuth账号、相同的简单直连卡片配置（允许与两端现有配置相同的模型字段）、文件凭证存储。代理/Stack、需要重新登录、无法控制的普通CLI、未知凭证代次和未决发布事务均停止并保留记录。需要人工系统操作的步骤按用户授权边界暂时搁置。

## 已完成的自动化验证

- Go回归与race：双向交换、空闲同号修复、候选刷新和未知字段保留、忙碌待用端、外部启动/文件修改、七个发布位置故障、未发布准备核查、已发布记录拒绝丢弃。
- Desktop协调器的暂停、退出、重启、设置核验和一次继续，在隔离运行适配器下验证。
- 真实本机Codex CLI进程＋合成凭证＋本地模型服务，经过新原生双目录后端完成暂停、退出、交换、重启、设置恢复和一次继续。待用Desktop/CC Switch生命周期使用隔离适配器；该测试不等于真实双账号服务验收。
- 真实账号分配修复通过：两端从同号变为不同账号，工作Desktop进程及认证保持，两端config字节不变，CLI指针同步；真实账号材料准备和写入实际执行。
- 安装版0.3.9显示两端账号与工作端入口。第一轮GUI实验暴露默认effort格式，已修复并通过同一真实会话的只读检查与回归；已知high effort不会被降级为default，内部default标记不作为API枚举发送。

## 暂时搁置的验收

第二轮安装版GUI使用真实额度和80%的临时实验阈值，已准备候选、发出暂停并确认轮次结束，但正常退出请求返回后Desktop进程持续存活，未交换凭证、未重启或自动继续。电脑控制工具禁止操作Codex自身界面，无法自动处理该界面条件，按用户要求暂时搁置，不反复请求授权、不强制杀进程。

同时发现退出时IPC读取失败会遮蔽45秒超时，现已修复：退出阶段只观察原进程树，超时即停用；确认未发布的准备事务可归档并恢复CC Switch，不回滚任何令牌。第二轮实验的准备事务已核查归档，CC Switch已恢复。此后出现另一份10%授权的准备事务：执行器已退出，记录为prepared且files为空，但工作端磁盘账号已从记录来源变为目标，两端磁盘账号相同。普通核查因此拒绝归档。用户随后确认手动切换，build20增加独立的手动替代核查入口，仅归档未发布准备，保留当前认证及所有恢复副本；自动切号保持禁用，未重试或回滚。

真实Desktop完整交换与冷启动、真实CLI工作端切号、自然耗尽触发仍未实机验收。旧0.3.7/0.3.8的单端实机结果不能代替新版双端结果。默认不为用户开启新自动化授权；待普通单会话环境或可处理退出条件后再补验收。

## 状态和诊断

```sh
"$HOME/Applications/Codex 小助手.app/Contents/MacOS/codex-helper" accounts status
"$HOME/Applications/Codex 小助手.app/Contents/MacOS/codex-helper" accounts check desktop
"$HOME/Applications/Codex 小助手.app/Contents/MacOS/codex-helper" accounts check cli
```

`handoff/state.json`原生授权使用版本2，旧版拒读，避免降级后误执行旧单端切号。`handoff/native-transaction.json`仅记录阶段、账号ID和文件摘要，凭证载荷保存在私有备份目录（0700/0600）。不确定刷新不重发，已经开始发布的事务不能通过普通确认清除。

仅对已停用、无未决动作、阶段prepared且未发布任何文件的事务，可使用“已检查，解除暂停”或以下命令核查。它保留当前最新凭证、恢复CC Switch，归档原记录和私有副本，不执行切号或继续任务：

```sh
"$HOME/Applications/Codex 小助手.app/Contents/MacOS/codex-helper" accounts recover-preparation
```

若用户明确确认在这份准备之后手动切号，可单独使用以下入口。它不会被自动恢复调用，且仍要求禁用、无未决动作、授权/两端/来源/目标绑定一致、prepared且files为空、两端当前身份均属于原有两个账号。它只归档记录，不修改当前认证、配置、账号分配或应用进程；未知刷新及已发布事务仍拒绝。

```sh
"$HOME/Applications/Codex 小助手.app/Contents/MacOS/codex-helper" accounts recover-preparation --manual-switch
```

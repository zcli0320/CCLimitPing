# 登录后启动与指定会话续跑（0.3.0）

## 登录后启动

主窗口底部勾选“登录后启动”。使用 macOS 原生登录项，显示系统实际状态；若系统要求允许，请在系统设置的登录项中允许。取消勾选即可关闭。这里是登录 macOS 用户后启动，不是尚未登录时运行。

## Desktop 原会话

1. 在 Codex 桌面应用中打开目标聊天。
2. 在小助手 Desktop 列表中选中同一会话，勾选“为选中会话自动续跑（不切号）”。
3. 会话明确因额度限制停止后，小助手每约 30 秒检查；当前账号五小时与周额度可用、原会话停稳且没有等待审批时，向原聊天发送一次“继续之前因额度限制中断的任务。”。

原会话使用原本的模型、推理与权限设置。小助手调用已运行桌面应用的原会话控制通道，不新开一个处理该聊天的后台进程。此本机通道为安装版本相关的内部接口，应用更新后如不兼容会显示等待/错误并停止，不退回模拟键盘点击其他聊天。

从 0.3.6 起，还会在检查额度前及发送前核对本地会话记录，要求会话 ID、最新轮次 ID 和完整结束事件一致。如果记录缺失、尚未写完、出现更新轮次或无法读取，会等待而不发送；遇到尚未确认的提交或仍处于 active 状态的目标（goal）也不会自动发送。由于内部通道没有提供发送时原子核对轮次和读取全部排队消息的接口，这只是额外保护，并不能完全消除用户恰好同时手动提交时的竞争。自然触限和恢复后的真实桌面续跑仍未验收。

## CLI 原会话

1. 选择 CLI 来源中的目标会话；若它已在另一终端运行，请先退出那里的 Codex 会话。
2. 点击“在终端托管续跑”，打开同一会话的托管终端。原会话历史继续使用 ~/.codex-cli；不复制聊天，不切换账号，不增加权限。
3. 正常在该终端使用 Codex。小助手从这个终端的同一个 app-server 读取结构化状态；仅在限额恢复后向自己的终端输入一次继续。

普通已经打开的终端无法被直接接管。检测到限额后若你又手动输入，本次交由你处理，避免自动输入覆盖编辑中的内容。退出托管终端会停止该会话的自动续跑；关闭续跑开关不会终止正常 CLI 工作。

## 开关与状态

一次只指定一个会话。更换会话/来源、会话归档/不可用或明确退出小助手，会关闭续跑授权；重新使用需要手动开启。标题变化不会改变绑定。主窗口关闭时，若有自动任务开启，会隐藏到菜单栏继续运行；菜单栏可以分别关闭预热或续跑。

凭证缺失、过期或被服务端拒绝，直接提示在 CC Switch 更新。小助手不刷新、不轮换凭证。更新同账号凭证后会重新检查；账号身份变化时，需要重新开启确认。

网络错误、一般 HTTP 429、正常完成、手动停止、审批或用户输入等待不会被当成额度停止。继续请求发送前保存去重记录；连接中断、写入中断或返回结果无法确认时，不自动重发，请查看原聊天/终端。续跑不受预热时段限制，预热时段仅限制预热请求。

没有新增自动切号、防休眠或唤醒恢复。

## 验证边界

已通过本地协议模拟、限额/恢复与异常状态测试、去重/手动介入/凭证失效测试、CLI 自有输入通道测试以及构建检查。真实桌面通道已做只读探测；本轮不为验收强行触发真实账号限额或续跑用户的其他任务。自然限额恢复后的真实续跑、完整注销再登录自启动，需与已验证的代码及系统注册状态分开看待。

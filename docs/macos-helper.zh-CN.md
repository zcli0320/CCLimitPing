## 使用

Desktop 切号：在 Desktop 页签选中准确会话，默认阈值10%，点击“为选中会话开启切号”。切换会退出整个 Desktop，其他会话和未提交输入可能受影响；开始前请在 macOS“隐私与安全性 → 辅助功能”允许安装版“Codex 小助手”，保持 CC Switch 已打开、目标卡片绑定唯一且配置目录为 `.codex`。小助手每约30秒检查触发条件；备用账号五小时剩余须高于阈值、周额度可用。停止按钮、换会话和退出小助手会撤销授权。系统权限或卡片识别失败时停止，不直接改写 CC Switch 管理的凭证。

CC Switch 的有效访问凭证目前仍从本机已有登录记录解析，用于只读额度预检；没有可用访问凭证时等待更新，不独立刷新。真正切号由 CC Switch 原有账号管理器准备最新完整登录记录。CC Switch 界面升级或更改卡片名称可能导致界面控制失效，失败会保留恢复记录。

双击 `~/Applications/Codex 小助手.app`。窗口提供：

- CC Switch 管理的 Codex 账号、已有供应商绑定、当前配置选择及默认账号；邮箱作部分遮盖。
- 每账号显示五小时／周窗口剩余百分比、重置时间、查询时间和匹配凭证的目录归属。启动及点刷新时读取服务额度，打开窗口期间每两分钟自动查询；中间每 30 秒只刷新本机会话并保留上次额度及其原查询时间。
- 会话区分为 **Desktop（`~/.codex`）** 和 **CLI（`~/.codex-cli`）** 两个页签，分别显示目录和数量。账号卡片仍来自 CC Switch，不能据此推断任一端的实际运行身份。
- 会话按项目目录分组，可展开／收起；项目及组内会话均按最近活动排序，显示会话数和最近活动时间。可按标题、项目或会话 ID 搜索，可包含归档会话。
- 选择准确的会话，再手动点“开始观察”，跟踪该会话记录的更新时间。它只观察本机记录，不能据此判断任务是否运行、账号是否生效或是否触及额度。
- 每 30 秒刷新本机数据，也可点“刷新”；可以直接打开现有 CC Switch。

换会话后观察停止；标题改变仍绑定同一会话；重启应用后保留选择，但需要重新开始观察。会话被归档、删除或读取失败时停止观察。归档对象仍可选中查看；临时读取失败或结果不完整时保留选择，但暂停观察。恢复后需手动重新开启。也可点“取消选择”清除绑定。

两端分别保留会话选择和项目展开状态，搜索只作用于当前页签。切换页签暂停助手的记录观察，回到原端后仍需手动开启；一端的目录缺失或读取失败不会使另一端的正常结果失效。历史会话按存放目录归类，`.codex` 中旧的 `cli` 来源记录仍保留在 Desktop 页签；这里没有移动或改写源记录。

搜索过滤不会把所选对象自动换成另一个会话；选中对象的名称仍显示在列表下方，被筛选隐藏时显示提示。无匹配结果会说明如何恢复列表。刷新时尽量保持正在阅读的会话位置，即使列表前方加入新会话。

项目按记录中的完整工作目录区分；名称相同、路径不同的项目分别收纳，名称旁补充父目录，没有目录的会话放入“未指定项目”。首次打开只展开所选会话所在项目（没有选择时展开最近活动的项目），之后保存手动展开状态。搜索时自动展开匹配项目；清除搜索后恢复原来的展开状态。折叠项目不会取消会话绑定或停止观察，界面会提示观察对象位于已收起的项目中。这里只调整呈现方式，不移动或复制历史文件。

“自动预热五小时窗口”已成为账号卡片下方可操作的独立开关；“自动切号 · 待接入”默认收起。“接入说明”显示读取提示、预热结果和 token 用量。窗口可缩小，内容超出时可滚动。预热关闭时关闭窗口即退出；开启后关闭窗口会隐藏到菜单栏继续检查，需从菜单明确退出。没有安装登录项。

## 数据和状态

数据桥接 `codex-helper snapshot` 是 App 内置的本地子进程，通过标准输出返回 JSON；没有 HTTP 监听端口。`snapshot` 只读取本机数据，`snapshot --quota` 额外查询各账号额度，输出仅包含解析后的额度字段。

| 数据 | 读取来源与规则 |
| --- | --- |
| 账号 | `~/.cc-switch/codex_oauth_auth.json` v2 中的本地账号标识和显示元数据；额度查询时读取其中身份声明以匹配用户与 workspace，认证字段不进入输出模型 |
| 额度 | 按 CC Switch 托管账号身份匹配 `.codex/auth.json`／`.codex-cli/auth.json` 中仍有效的 access token；仅向固定的 `https://chatgpt.com/backend-api/wham/usage` 发 GET，禁止重定向，按 CC Switch `services/subscription.rs` 的窗口时长字段区分窗口 |
| 供应商绑定及选择 | 对 `cc-switch.db` 使用 SQLite `-readonly`，只查询供应商显示字段和 `authBinding.accountId`；优先采用 `settings.json` 中当前供应商标识，沿用供应商排序。多个数据库选择标记不作为已确认选择；匹配失败显示提示 |
| Codex 目录 | 按用户已做的分割固定读取 Desktop `~/.codex` 与 CLI `~/.codex-cli`；CC Switch 的 `codexConfigDir` 仅作为配置来源信息展示，不把两个读取入口重定向到同一目录 |
| 会话 | 分别只读每端的 `state_*.sqlite`、标题索引与会话目录，各自支持 `config.toml` 的 `sqlite_home`；隐藏子代理会话，每端最多返回最近 2000 个会话 |
| 标题 | 区别于首条消息的数据库标题 → `session_index.jsonl` 最新有效标题 → 首个有效用户问题 → 项目名。超大索引读取最后 8 MiB，优先保留最近重命名，并显示读取受限提示 |
| 文件回退 | 数据库不可用时，有限度读取 `sessions/` 与 `archived_sessions/` 中 JSONL/Gzip 文件元数据；跳过注入上下文，按 ID 去重；按修改时间优先读取最近 4000 个文件，每个最多读取 1 MiB。回退／较旧数据库／截断等情况明确标记为非完整结果，暂停观察 |
| 本地选择 | `~/Library/Application Support/CodexHelper/ui-state.json`，保存当前页签、两端各自的选择 key、项目展开状态和观察状态；目录权限 0700，文件权限 0600。会话 key 包含端与历史目录上下文，相同会话 ID 不会串绑 |

不保存聊天正文或聊天副本，不维护另一套凭据。额度查询只在内存短暂使用已有访问凭证；不读取 refresh token 字段、不轮换凭据、不写入源文件。额度查询不调用模型；用户开启预热后才由独立 app-server 临时会话发送一次小请求。查询值只在窗口进程内保留，没有额度或凭证持久化缓存。损坏或超大的 JSON 不保留部分解析结果。网络／数据库／JSON 错误只返回固定说明，不回显响应体、请求头或可能含凭证的错误文本。GUI 对自己的读取子进程另设 20 秒超时和 16 MiB 输出上限，额度请求另有 10 秒超时；超时后恢复刷新按钮，不会终止 Codex 或 CC Switch 进程。

历史中的 `cli` 或 `vscode` 等来源只表示历史客户端类别。尤其 `vscode` 不足以区分 IDE 与 Desktop，更不证明当前实例、账号或控制连接。

## 0.3.3 自动切号只读检查与隔离原型

用户选中会话后，可输入默认 10% 的阈值，使用“检查所选会话”只读检查来源账号额度、备用账号额度及当前接入障碍。此检查不授予自动交接权限，不中断会话、不换号、不重启、不发送继续或模型请求。磁盘身份不代表运行中的实际身份；可用访问凭证也不代表完整凭证可安全换号。

本版另有隔离状态机，测试了阈值、备用额度/认证检查先于停任务、阶段登记、单次继续、用户干预及结果不明时不重发。它没有生产 Desktop 或 CLI 执行适配器，不能用于自动切号。Desktop 当前 follower 中断会影响子代理，主动收尾接口无法绑定预期轮次；所有活动聊天、后台工具及重启后运行账号尚不能完整核验。CC Switch 的凭证轮换锁位于其进程中，磁盘快照一致也无法证明不会并发轮换。故本版在这些问题解决前明确保持不可执行状态。

## 0.3.4 直接认证候选与隔离切换

按用户确认的直接文件方案，检查现有 Desktop、CLI 和 CC Switch 暂存中的完整原生认证。候选需与托管账号的用户、workspace 和当前刷新凭证一致，访问凭证未过期，并通过对同一候选的额度查询；从不同记录拼接认证不被接受。完整认证与可查询额度是两项不同结果，刷新凭证是否受服务端接受还需实际使用验证。若 CC Switch 内的认证已比暂存更新，要求更新可用的完整记录；助手不自行刷新。

新增认证替换及恢复逻辑：交接授权、准确来源与目标、进程已停稳、备用额度、目标文件和候选文件均需复查；认证原子替换前保存私有恢复副本和事务记录。恢复时仅在目标文件仍为本次写入的内容且实例已退出时覆盖；经运行实例身份核验后清理恢复副本。该逻辑已通过虚构凭证与模拟交接的隔离测试，包括文件并发修改、错误身份、过期、权限、意外退出恢复和重复保护。

生产自动交接尚未接入该替换逻辑；没有在真实账号上执行切号、重启或继续，也没有验证 Desktop 与 CLI 的真实端到端切号。独立进程仍可能在最后一次检查与文件替换之间变化；后续适配器必须确认原实例退出，并在重启后验证实际账号。原 0.3.3 的“必须接入 CC Switch 内部锁才能切号”不是当前方案的前置条件。

## 0.3.5 托管 CLI 自动切号

1. 在 **CLI** 页签选择需要托管的原会话。若同一会话已在其他终端运行，先在该终端退出它。普通已有终端不会被自动接管。
2. 可先点“检查所选会话”，检查当前目录账号、备用账号额度及完整认证候选。默认阈值是五小时剩余 **低于 10%**，可在开启前修改。
3. 点“托管并开启切号”，在新打开的终端里继续使用该会话。仅选择会话不会开启交接；不切号续跑与托管切号不能同时启用。
4. 达到阈值且备用账号完整认证、五小时及周额度符合条件时，小助手请求原轮次收尾；必要时中断准确轮次。确认工具、后台终端及同一后端其他会话停稳后，正常退出旧进程，切换完整认证，重启并核验原会话、账号与执行设置，再发送一次继续。
5. “停止切号”取消后续自动交接；若动作正在进行或结果不明确，界面会保留暂停状态，不能盲目重发。认证恢复记录存在时，关闭托管终端并核查当前账号和会话后，可选择保留当前认证、清理恢复副本并解除暂停。

后台终端存在时等待，不自动终止；旧后端收到退出信号后等待进程实际退出，最多等待 45 秒，超时暂停交接。临时恢复副本受本机文件权限保护，正常交接验证后清理。小助手不主动刷新或轮换 refresh token；认证不可用时在 CC Switch 更新。

实机 GUI 确认了 0.3.5、登录启动和原预热时段仍启用，选择 CLI 会话后托管入口可用，选择操作未开启切号。启动时曾短暂退回不完整的 CLI 文件读取，刷新后数据库读取恢复；不完整状态会禁用托管入口。真实服务在独立临时目录验证了切换及一次继续轮次开始，测试使用无效的测试 refresh token 和模拟阈值，未对实际认证文件执行切换，也未验证自然触限和新轮次最终完成。Desktop 自动切号仍未接入。

# Codex 小助手：使用与构建

当前源码版本为 **0.5.0 / build 48**（最低系统要求 **macOS 13.0 Ventura**）。本版延续账号测试版的账号库和自动化状态，采用原生 SwiftUI `NavigationSplitView` 单窗口四工作区架构、统一顶栏 `Toolbar`、原生 `Settings` 设置窗口（`Cmd+,`）与标准菜单快捷键（`Commands`）。主窗口左侧边栏固定四大目的地：

1. **概览（`Cmd+1`）**：汇总账号与额度、自动预热、会话续跑/切号、项目协作（严格区分**执行中**与**排队中**任务数）四张跳转卡片，以及快速启动 Codex CLI / AGY CLI 与受管 AGY 监测入口。
2. **账号与额度（`Cmd+2`）**：集中管理小助手与 CC Switch 账号卡片、5 小时/周额度进度、Desktop/CLI 绑定状态，以及自动预热开关与允许时段配置。
3. **会话与续跑（`Cmd+3`）**：按项目分组浏览 Desktop（`~/.codex`）与 CLI（`~/.codex-cli`）历史会话，支持 `Cmd+F` 搜索过滤、只读观察、同账号续跑、自动切号交接核验与阈值配置。
4. **项目协作（`Cmd+4`）**：项目工作群与任务回执工作台。顶部常驻项目切换、执行器状态与操作栏（`Cmd+Shift+N` 新建项目、`Cmd+N` 新建任务）；主区采用左任务列表（无横向滚动、严格区分执行中/排队中/待验收）+ 右选中详情双栏设计，窗口宽度低于 `1100` 时自动折叠辅助详情并提供返回任务列表导航；任务操作栏按状态展示可用动作并显式说明不可用按钮原因，详情分为“实时进度与阶段”、“任务卡与审查结论”、“执行回执与检查证据”三部分。

## 原生设置窗口（`Cmd+,`）

点击主窗口右上角工具栏齿轮按钮或按 `Cmd+,` 可打开原生 `Settings` 设置窗口，包含三个标签页：

- **通用**：开机自动启动开关、当前版本与状态存储目录路径、接入说明入口。
- **启动与恢复**：快速启动目录策略（每次询问或固定工作目录、最近目录列表、YOLO 权限说明），以及 AGY 会话监控与网络异常有限自动恢复配置（默认关闭，支持 20 分钟暂停窗口）。
- **协作**：执行器（Runner）偏好设置（随小助手启动、Desktop 关闭时自动切号、自动返工上限）、Codex 执行器账号来源（使用 Desktop 账号或独立账号 `~/.codex-runner` 登录/退出）以及主控代理 MCP 配置查看与一键复制。

## 快捷键与菜单命令

- `Cmd+1` / `Cmd+2` / `Cmd+3` / `Cmd+4`：在“概览”、“账号与额度”、“会话与续跑”、“项目协作”四个顶级目的地之间切换（状态自动持久化到 `ui-state.json`）。
- `Cmd+R`：刷新当前页面数据（在“项目协作”页刷新协作与任务状态，其余页面刷新账号与会话快照）。
- `Cmd+N`：新建协作任务（仅在“项目协作”页可用）。
- `Cmd+Shift+N`：新建协作项目（仅在“项目协作”页可用）。
- `Cmd+F`：聚焦会话搜索框（仅在“会话与续跑”页可用）。
- `Cmd+,`：打开设置窗口。

## 代理协作

在“项目协作（`Cmd+4`）”页面可直接管理项目工作群与任务生命周期，低频的执行器策略、独立执行账号（`~/.codex-runner`）登录与 MCP 配置统一收拢在 `Settings → 协作` 标签页（也可从协作页工具栏一键直达）。主控代理可按照 `Settings → 协作` 中复制的 MCP 配置连接并派发任务，界面支持新建、停止、确认已停止、一键断点续跑、补充指令继续、打回返工和验收通过。执行器异常中断时，尚未完成的任务不会自动重跑：请先检查相关进程是否都已停止，再点“确认已停止”（或 `codex-helper orchestra confirm-stopped <id>`）确认，之后才能返工或继续。

### 项目（工作群）

“项目（工作群）”把同一个工作目录的任务归在一起。点“新建项目…”填写名称、编号、工作目录、执行者，可选审查者、检查命令（每行一条）和允许改动范围（每行一个路径前缀）。选中项目后，任务列表只显示该项目的任务，“新任务”会自动使用项目的执行者、目录、检查命令和改动范围。命令行对应 `codex-helper orchestra project create|list|get|archive`、`dispatch --project <id>` 和 `list --project <id>`；MCP 对应 `create_project`、`list_projects`、`get_project`，`dispatch_task` 可只给 `project`。

项目设置了审查者（且不是派活的主控）时，执行者交回回执并通过检查后，任务进入“审查中”，系统自动给审查者派一个只读的审查任务（编号为 `<任务>-r<轮次>`）。审查者在回执末尾给出 `VERDICT: PASS` 或 `VERDICT: CHANGES`：通过则任务回到“待验收”；需修改且还有自动返工次数时，审查意见作为返工交回原执行者，否则回到“待验收”并显示审查意见；审查失败或无法派出时标记“审查不可用”并写明原因。审查中也可以直接验收或停止，审查任务会一并取消。主控的 `wait_task` 会等审查结束才返回。归档项目只是不再在列表中显示，已有任务记录保留。

## 账号与会话

在主界面的“授权管理”中添加、重新登录或移除小助手的账号授权。账号卡片合并显示小助手与 CC Switch 的账号信息；仅来自 CC Switch 的账号不会因此获得小助手的凭证或切号权限。卡片上的“当前”根据对应目录的登录文件判断，运行中的客户端身份需要另行核验。

Desktop 和 CLI 的会话分别按 `~/.codex` 与 `~/.codex-cli` 目录展示。应用账号到某一端前，需要退出使用该目录的客户端及其后端；CC Switch 管理同一目录时要按界面的归属提示操作，避免并发写入。另一端的登录文件不会因为此操作被改写。CC Switch 管理 Desktop 时，请通过 CC Switch 切换 Desktop 账号。

预热、同账号续跑和自动切号均需用户主动开启；预热会发送真实请求。每项功能依赖账号、额度和运行状态检查，失败时按界面提示处理。账号数据和恢复备份包含敏感凭证，保存在本机私有目录中，不应提交到仓库。

## Desktop 自动切号

1. 在 Desktop 页签选择需要监控的会话。若要建立运行账号核验连接，先正常退出 Desktop，再使用“核验方式打开 Desktop”。
2. 确认备用账号额度、当前运行身份和选中会话，点击“检查所选会话”。需要时在 macOS“系统设置 → 隐私与安全性 → 辅助功能”允许当前安装的小助手控制电脑，并确保 CC Switch 正在运行。
3. 检查通过后，手动开启该会话的切号。默认阈值为五小时剩余 10%，可由用户调整。触发时会暂停所选会话并退出整个 Desktop，其他会话和未提交输入可能受到影响。
4. Desktop 由 CC Switch 管理时，小助手调用 CC Switch 的卡片切换，并核验实际写出的登录状态；无法确认时停止并保留需要核查的状态。停止或退出小助手会撤销自动交接授权。

自然额度耗尽后的完整交接仍需实机验证；模拟额度触发、隔离服务测试和单独的辅助功能检查不能代替这一验证。运行身份连接不可用、目标卡片不唯一或系统权限不足时，自动交接不会继续。

## 状态与升级

为了沿用账号测试版的数据，本版保留 `local.codex-helper.account-preview` 应用标识和 `~/Library/Application Support/CodexHelper-AccountPreview/` 状态目录。目录名称是兼容标识，不表示另有一套正在运行的测试版。旧 0.3.8 的 `CodexHelper` 状态目录不会自动覆盖本版数据。

本机持续更新建议使用固定代码签名身份。构建会自动读取 `~/Library/Application Support/CodexHelper-Signing/identity` 中的证书 SHA-1 指纹，也可用 `CODEX_HELPER_SIGNING_IDENTITY` 指定钥匙串身份，或用 `CODEX_HELPER_SIGNING_IDENTITY_FILE` 指定指纹文件。证书和私钥保存在用户钥匙串，私钥不得提交到仓库。配置存在但无效、证书不可用或签名失败时，构建会报错，不会退回临时签名。

没有配置签名身份的开发环境仍使用 ad-hoc 签名，并输出提示。这种签名会随构建改变，辅助功能可能需要重新授权。从 ad-hoc 切换到固定证书也需重新授权一次；后续更新须保持应用标识和签名身份一致，并验证授权保留。本机自签名适用于本机开发；公开分发应使用 Developer ID。登录后启动也请在安装后检查其状态。

## 构建和验证

需要 Go、Rust/Cargo、Xcode 命令行工具与 macOS Cocoa 框架。在仓库根目录执行：

```sh
go test ./...
go vet ./...
bash scripts/build-macos-helper.sh
```

若工具链不在 `PATH`，可通过 `GO_BIN` 和 `CARGO_BIN` 指定可执行文件；在离线环境可设置 `CARGO_NET_OFFLINE=true` 并使用已有的 Cargo 缓存。脚本构建 `bin/limitping` 和应用依赖，输出 `dist/Codex 小助手.app`，并执行深度严格签名验证；构建不会自动安装应用。

隔离端到端检查可运行 `scripts/run-isolated-loopback-tests.sh`，使用虚构账号和本机模拟服务，并需要本机已安装的 Codex 后端；检查脚本将跳过视为失败。不得把隔离测试结果当作真实账号交接验收。

账号管理器部分代码来自 CC Switch；版权和 MIT 许可见 `native-accounts/CC-SWITCH-LICENSE`，也会随应用打包。

# 自动预热五小时窗口

版本：0.2.1 / build 8。日期：2026-10-26（Asia/Singapore）。

双击 `~/Applications/Codex 小助手.app`，勾选账号卡片下方的 **自动预热五小时窗口**。开关默认关闭；开启时将当时 CC Switch 管理的账号纳入预热，之后新增账号需要重新开启。GUI 显示各账号等待或执行原因，“检查一次”立即执行一次调度检查，不会强制给已运行的窗口补发请求。

0.3.2 起，现有 Codex 目录没有某账号的可用凭证时，助手会只读尝试 CC Switch 本机原生登录暂存，核对用户和 workspace 并检查有效期；服务端仍须接受凭证。暂存不是自动续期服务，过期或被拒绝时仍需通过 CC Switch 更新；暂存账号不对应明确运行目录，因此预热前保守检查 Desktop 与 CLI 两边的近期活动。

账号卡片下方的“自定义时段”可设置每日开始／结束时间。勾选“仅在指定时段允许预热”后保存，时区固定为 Asia/Singapore（UTC+8）；支持如 22:00–次日 08:00 的跨午夜时段。开始时间包含在内，结束时间不包含；相同时间不能保存，全天允许请取消勾选时段限制。保存时段不会改变自动预热开关或重置请求登记。旧版本升级默认全天允许，示例 08:00／23:00 不代表自动启用了该范围。

时段外不发起新的预热请求。到达下次开始时间后重新检查窗口，不补发过去错过的请求，也不会暂停已经启动的五小时窗口。准备期间修改时段或跨过结束时间，提交前会重新读取设置并取消不再允许的请求；已提交的一次请求仍完成回查。手动“检查一次”也遵守时段限制，普通额度卡片刷新仍可正常读取。

开启后，每分钟检查。关闭窗口会隐藏到菜单栏，预热继续运行；菜单栏太阳图标可重新打开窗口、关闭预热或退出。退出应用停止后续调度，当前独立执行会收到取消信号；已登记的请求结果不明确时，下次不会直接重发。重新打开应用会按保存的开关重新开始检查，没有安装开机登录项。

Mac 睡眠时不能执行，唤醒后重新查询。它不能强制重置服务器额度、增加周额度或囤积窗口。

## 请求条件

| 条件 | 行为 |
| --- | --- |
| 五小时窗口已运行 | 等待该窗口重置，不补发 ping |
| 窗口未启动／刚重置 | 至少两次读取确认空闲，再做执行前检查 |
| 周额度耗尽 | 等待，不发送请求 |
| 缺少五小时或周窗口／网络错误 | 标明未知或错误，延后查询，不当成可用窗口 |
| 没有与 CC Switch 托管账号匹配的有效访问令牌 | 等待 CC Switch／原客户端刷新，不自行轮换 refresh token |
| 对应目录近期有任务活动 | 暂缓，由正常工作请求启动窗口 |
| 用户关闭、移除账号、凭证或窗口状态改变 | 提交前取消 |
| 已登记可能发出的请求，但结果不明确 | 只回查；登记后五小时加 30 秒内不再发送 |

状态由额度 API 的窗口时长、用量、重置时间和倒计时判断。未启动的窗口可能返回随查询移动的整五小时重置时间，因此不能只因 `reset_at` 在未来就认定已启动。服务端倒计时缺失时使用带容差的本地时间比较；不明确时再次查询。

## 执行与隔离

本机已验证的 Codex CLI 0.164.0 app-server 通过 stdio 提供外部访问令牌认证。助手只匹配 CC Switch 托管账号的现有有效访问凭证，临时进程使用独立 HOME、CODEX_HOME、XDG 目录和空工作目录。它不切换 CC Switch 当前供应商，不临时覆盖 `.codex`／`.codex-cli` 的 auth.json，也不复制刷新凭证或用户配置。

执行顺序为初始化 → 外部令牌认证 → 读取该账号模型目录并选择轻量模型／低推理强度 → 创建 ephemeral 线程 → 持久登记请求 → 提交一轮“Reply OK.” → 检查完成事件和用量 → 再查询额度确认窗口运行。只有进程退出成功不算预热确认。没有工具或刷新授权；遇到相关请求会停止。

外部令牌登录和协议使用实验性能力，按本机生成 schema 与实际预检实现；版本不兼容时显示执行失败，不回退为修改主环境凭证。参考 [OpenAI App Server 外部令牌认证与线程协议](https://learn.chatgpt.com/docs/app-server)。

## 状态与防重复

助手自身状态目录：`~/Library/Application Support/CodexHelper/warmup/`。

- `policy.json`：开关和启用时账号集合的哈希。
- `journal.json`：身份哈希、显示名、窗口状态、请求登记、完成／用量、下次检查时间及不重发期限。没有 token 或完整账号标识。
- `execution.lock`：一次只允许一个检查进程持锁；`policy.lock` 协调开关更新。

状态文件以私有权限写入、同步并原子替换。提交前必须写入登记；状态损坏会停止请求，不自行抹掉登记重新发送。同一用户与 workspace 的多条账号记录按身份哈希去重。

“接入说明”可查看最近一次每账号的模型和实际 token 用量。状态只保存最近结果与累计登记次数，没有复制聊天历史；临时执行目录结束后删除。

## 已验证与未验证

已验证：

- 两个账号分别完成一次独立真实请求、结构化完成事件、token 用量和额度回查。
- 模型 `gpt-6-luna`、effort `low`；每次输入 6549、输出 5、总计 6554 tokens，其中一次缓存输入 4864。提示很短不等于总输入很少。
- 两次测试前后 `.codex`／`.codex-cli` 的认证与配置、CC Switch 账号源与设置哈希一致。
- 自动调度单元测试覆盖运行窗口跳过、模拟重置后二次确认、每账号一次、防重复、断开后不重发、活动任务、用户关闭、提交前正常工作启动窗口、并发锁及状态损坏。
- 隔离执行预检确认临时会话、外部认证模式与无 auth.json 落盘。

仍有边界：两次真实测试在窗口已运行时单独发起，用于验证执行路径，不能当成“自然重置后自动预热”的长时间验收。原客户端或 CC Switch 负责凭证续期；凭证过期时本版等待。完整睡眠／唤醒、重启后的长期运行尚未实测。CLI／Desktop 原会话自动切号续跑不属于这次预热功能。

开发桥接命令（正常使用不需要终端）：

```sh
bin/codex-helper warmup status
bin/codex-helper warmup enable
bin/codex-helper warmup check
bin/codex-helper warmup disable
```

开发用 `warmup probe <托管账号标识>` 会发真实请求，即使窗口已运行；同账号 24 小时内不重复登记测试，GUI 不提供强制测试入口。


## 时段功能验收（0.2.1）

已测试普通／跨午夜时段、UTC+8 时区、开始包含与结束排除、下次允许时间、时段外调度不触发模型、准备期间修改设置、最终额度查询跨过结束时间、旧设置兼容，以及保存时段不改变自动开关和账号集合。原生时间选择器支持自定义输入、跨午夜提示、保存后重新读取、同时间禁止保存。

本轮没有增加真实模型请求，保留先前实测的 gpt-6-luna / low、每账号输入 6549、输出 5、合计 6554 tokens。无法仅按 token 数换算成固定五小时百分比；[官方额度说明](https://learn.chatgpt.com/docs/pricing)指出模型、上下文、推理、工具与缓存等都会影响订阅额度。先前真实测试没有保存独立的预热前后额度差值，不能声称每次固定消耗某个百分比。

GUI 隔离验收改用显式 `CODEX_HELPER_TEST_HOME`，要求测试根目录存在专用 marker，且不能指向真实用户目录；无效时停止读取，不回退。测试中曾发现 HOME 环境覆盖未生效，短暂把测试时段写到助手自身设置；已恢复为不限制时段，原自动开关保留，没有修改 Codex／CC Switch 认证或配置。
